# {{PROJECT_NAME}} 项目规则

先读 README.md、project.json、项目说明.md、任务清单.md，再按当前任务读取需求与设计.md、决策与变更.md。

采用的统一规则在 `.project-baseline/rules.md`，版本为 {{BASELINE_VERSION}}。项目事实与差异在本项目维护，不修改快照。

默认顺序：明确目标、探索方案、建立工程、数据与接口、核心功能、命令验证、界面、验收。不适用阶段写明理由；不能跳过完整性检查。

源代码默认放 src/，验证放 tests/，探索放 prototypes/，本地数据与回执放 .local/。先查现有实现再增加文件。

遵守快照 rules.md 的资源复用与磁盘预算规则。模型、字体和媒体原料默认共享引用；测试不得按用例复制资源。改动生成或打包入口后检查重复资源及空间增量，保存证据。离线交付按清单携带必要资源，禁止嵌套旧包和缓存；硬链接仅用于不可变文件，禁止原地写入。

范围变化先更新决策与需求，再写代码。任务状态必须有证据。模拟数据通过、自动检查通过、可操作试用与人工验收分别说明。不要逐步骤向用户重复请求已授权的操作。
