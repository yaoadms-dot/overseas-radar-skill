# 软件项目统一开工标准

## 原则

先明确要解决的问题、使用者、范围和完成标准。一次建立一条完整可用的流程，再逐项扩展。已经有资料或代码时先查现状，不要求用户重复提供可查到的信息。

已知事实、用户决定、实施建议和待确认项分开记录。需要用户决定的范围变化集中说明，普通实现选择由执行者自主完成。

## 流程

明确目标 → 探索方案 → 建立工程 → 数据与接口 → 核心功能 → 命令验证 → 界面 → 验收。

明确目标要写使用者、问题、实际场景、范围和完成标准。探索原型单独保存在 prototypes/ 中，记录选择依据；原型不能充当已完成的正式功能。

建立工程时固定项目规则、独立 Git、目录约定与任务清单。设计先明确输入输出、状态与关系、失败处理及可核对的样例。核心能力按模块实现，通过 CLI 或等价可重复入口验证后，再接正式界面。UI 与 CLI 共用同一业务实现。

不适用的探索、数据、核心功能、命令或界面阶段可以写明原因后跳过，但基准完整性、明确目标、建立工程、最终验收不可跳过。不得为了满足模板而引入无用的数据库、服务或技术栈。

## 文件与变更

需求、设计、任务、决策与验收分别有明确入口。业务代码默认放 src/，检查放 tests/，原型放 prototypes/，本地数据和运行回执放 .local/。确有框架约束时在项目说明记录调整原因。

新想法先进入决策与变更；影响范围、接口或验收时，更新依据再实施。先检查旧实现再新增文件。任务完成必须关联证据；进度文件是唯一状态来源。

## 验证与交付

按改动风险运行适当检查，避免只复述实现的测试。记录命令、输入性质、实际输出和退出码。将演示验证、自动检查、可操作试用、人工验收分开，不越级宣称完成。

错误必须可定位，失败不能污染已有有效状态。存在持久化时验证关闭与重启；有界面时实际完成核心交互，不以页面打开成功替代功能验收。

交付给出稳定入口、使用方法、版本、证据、未完成边界及接手方法。用户验收只能由真实用户记录支持，自动化或 Agent 操作不标为人工验收。

## 资源复用与磁盘预算

模型、字体、媒体原料、运行时和依赖必须区分唯一来源、开发缓存、任务输出及离线交付。开发任务和参数化测试只生成本次变化的输出，优先引用共享资源；禁止按样式、用例、重试或候选版本递归复制整套资源。复制目录前检查包含项、目标大小及是否嵌套旧产物。

设计阶段登记资源来源、版本或 SHA-256、大小、可变性、使用方、共享方式、输出目录、预算、负责人及保留期限。不可再生原料、客户输入、历史任务和必须留存的证据不得按重复文件报告自动删除。

共享引用优先；同盘硬链接只用于确认不可变的资源，必须校验内容、保留路径并记录链接关系。硬链接共享同一文件内容，禁止原地修改；更新资源先生成新版本，再替换引用。跨盘或不支持链接时不得悄悄退回全量复制，须说明实际空间增量和替代方案。共享目录不能代替备份。

离线交付可携带必要字体、模型和运行时，但必须按清单打包、校验版本与许可证，并在无开发缓存的环境验证。禁止把开发缓存、测试输出、旧交付包、验收解压目录再次包进新版本。独立交付、合法备份或跨平台资源的重复需记录用途和保留期限，不能仅凭同名或同哈希删除。

修改复制、生成或打包逻辑后，以及命令验证、最终验收前，运行快照中的 `tools/audit_resources.py`，保存 JSON 证据。默认检查大于等于 1 MiB 的文件，独立重复资源估算达到 256 MiB 时返回 1，扫描不完整返回 2；硬链接按一个存储对象计数。项目可记录不同预算、排除范围和必要副本的依据，不得为了通过而随意提高阈值。工具默认排除依赖缓存目录，须另行记录这些目录的体积与回收策略；报告不是全盘扫描或删除许可。

每轮测试登记临时输出的归属和期限；证据保存后清理已确认无用的本轮产物。阶段结束比较新增磁盘占用与预算。已有项目须显式采用并接入检查，不自动修改旧快照；发现增长须修正实际生成入口并验证，不能只对现存文件去重后宣称根因已修复。

## 版本与快照

.project-baseline 保存不可变的模板、规则、工具和清单；project.json 是可变项目配置。不要直接编辑快照。升级基准必须记录决定、版本差异与迁移结果。

每个实质阶段记录 Git 提交。Git 提交不等于远端备份或用户验收。凭据、真实输入资料与临时运行文件不得进入仓库。

## 跨平台执行

Windows 使用 `pwsh` 入口；macOS/Linux 使用 `sh` 入口。三种系统共享同一 Python 引擎、模板清单、快照格式、退出码与 Git 提交规则。不得因平台差异跳过基准完整性检查。

既有项目不重建；要新增 `BASELINE_ADAPTATION.md`，说明采用的母版版本、无法采用初始化快照的原因、现有 Git 基线、阶段证据和未完成检查。该适配记录不等同于 `.project-baseline` 完整性验证。
